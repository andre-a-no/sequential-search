# ADR-001: Узлы графа — это эксперименты, рёбра — статистические решения

## Статус
Принят (обсуждение от 2026-10-31)

## Контекст
`sequential-analysis` решает задачу последовательного статистического вывода на
плоском потоке наблюдений. Мы строим `sequential-search`: ядро, которое делает
то же самое, но **в процессе обхода графа**, где классический бинарный тест —
вырожденный случай (граф из двух узлов / одно ребро).

Ключевой вопрос онтологии: чем является узел и чем является ребро.

## Решение

### Узел = процедура сбора данных + состояние накопленных улик
Узел — это не «данные» и не «гипотеза». Это **эксперимент**: объект, который
умеет выдавать наблюдения по запросу (`step()`) и хранить накопленное
состояние (`state()`). Гипотезы, сэмплы, стадии пайплайна, воксели томографии,
уровни пирамиды изображений, действия агента — всё это интерпретации узла,
которые живут в прикладном слое `sequentialist-search`, а не в ядре.

### Ребро = stopping rule, решающая «делать ли переход»
Ребро содержит статистическую процедуру и правило остановки. Проходимость
ребра — это статистическое решение, а не булев предикат. Булев предикат —
вырожденный случай правила с нулевой долей риска (детерминированная граница).

### Обход = политика + глобальный бюджет ошибок
`Traversal` связывает граф, политику выбора следующего узла и глобальный
контроль ошибок. Инвариант ядра: family-wise error ≤ α по всему обходу,
обеспечивается через e-values / alpha-spending на уровне рёбер
(evidence.py, error_budget.py). Политика не знает про статистику,
статистика не знает про граф.

## Следствия: шесть нетривиальных интерпретаций графа

Онтология «узел=эксперимент, ребро=решение» покрывает все обсуждённые
постановки без изменений в ядре:

1. **Каскад фильтров** (pipeline): узлы — стадии, рёбра — пороги
   pass-through. Классика group-sequential.
2. **Адаптивное дерево условий** (sampling): узлы — точки сбора, рёбра —
   решения «продолжать ветвление или нет».
3. **Поток гипотез** (hypotheses): узлы — гипотезы, рёбра — переход по
   рангам online-FDR (LORD/LTSI). Зависимости между узлами задают
   graph-based FDR (например, SMS-tree procedures, Li & Barber).
4. **Карта состояний HMM / change-point**: узлы — режимы, рёбра —
   вероятности переключения; обход = траектория CUSUM/BOCPD.
5. **Иерархическое углубление (томография, пирамиды)** — важнейший кейс:

   ### Кейс «томографии в глубь»
   Поиск патологий в K-срезной томографии как **бинарный/DFS-поиск по
   дереву разрешения**:
   - Уровень 0: среднее по всем слайсам → решение, есть ли сигнал вообще.
   - Уровень i: усреднение групп по 2^i слайсов → на каждом ребре SPRT-
     подобный тест «спускаться ли к более тонким слайсам».
   - Листва: одиночные слайсы, детальная классификация.

   Это даёт **экономически оптимальную стратегию**: дорогой просмотр
   тонких слайсов оплачивается только когда дешёвое усреднение дало
   значимую улику. Тот же каркас — для image pyramids (от low-res к
   high-res region of interest) и для любого coarse-to-fine поиска.

   Отсюда важное требование к ядру: **стоимость наблюдения различается
   по уровням графа**. Бюджет — не только α-риск, но и ресурс (кадры,
   токены, CPU). Нужен resource-aware budget: политика выбирает следующий
   узел по ожидаемой информации на единицу стоимости (value of information).

6. **Стохастические политики агентов** (action search): узлы — продолжения
   действия, рёбра — статистические решения «продолжать / отбросить /
   разветвить». Агент выходит из эвристик: вместо «делать N шагов и
   посмотреть скор» — anytime-valid критерий на каждом шаге rollout'а
   (perpetual traversal, остановка в любой момент без нарушения гарантий).

## Требования к архитектуре, вытекающие из этого ADR
- Node: Protocol { step(cost) -> Observation; state() -> EvidenceState }
- Edge: guard(EvidenceState) -> StoppingDecision (accept/reject/pending)
- Traversal: поддерживает finite и perpetual режимы; чекпоинтится целиком.
- error_budget: два режима — offline (классический) и online (e-values,
  работоспособны на DAG и при адаптивном выборе следующей проверки).
- Рёбра несут флаг independence-предположения; для зависимых случаев —
  graph-FDR процедуры.
- Стоимость узла входит в API: `Node.cost` и `Budget(resource=...)`.

## Что остаётся в sequential-analysis
Ядро не переписывает математику: SPRT, group-sequential, mSPRT, e-values,
CUSUM, BOCPD берутся как зависимости; `stats/procedure.py` — тонкие
обёртки, сохраняющие формат чекпоинтов и RNG-семантику.

## Вырожденный тест-якорь
Граф root→leaf с одним ребром и фиксированным порогом должен давать
статистически идентичный результат standalone-прогону SPRT из
`sequential-analysis` (тот же лог likelihood ratios, та же остановка).
Это — спецификация, фиксируется в tests/ до реализации обхода.
